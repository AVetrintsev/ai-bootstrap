# 16: Включить публичный HTTPS и переключить работающий портал

**What to build:** Владелец может установить платформу сразу с публичным HTTPS или перенести существующий портал с локального HTTP на домен повторным запуском установщика с обновлённым YAML. Для внешней приёмки нужен выбранный домен с записью `A` и доступными портами `80` и `443`.

**Blocked by:** 07 — Подключить GitHub и добавить приватный проект.

- [x] `https` используется по умолчанию. В этом режиме домен и ожидаемый входящий IPv4 проверяются до изменений служб. С работающим mihomo установщик сверяет публичную запись `A` с ожидаемым адресом и останавливается при неожиданном `AAAA`.
- [x] Nginx обслуживает HTTP-01 на `80` и перенаправляет обычные запросы на HTTPS. Let's Encrypt выдаёт доверенный сертификат с автоматическим продлением. Ранний тест через Globalping подтверждает ожидаемый IP и порт `443`, доверенный TLS, статус `200` и точное новое содержимое временного маршрута.
- [ ] Временный маршрут удаляется и при успехе, и при ошибке. Ошибки DNS, TLS, входящего маршрута и недоступность Globalping различимы. Неудачное переключение оставляет локальный вход доступным через SSH-туннель.
- [ ] Успешное переключение выключает локальный HTTP-вход. Существующие проекты, рабочие копии, авторизация GitHub App, данные и секрет TOTP сохраняются. Владелец регистрирует браузер на домене текущим TOTP. Сессионная cookie получает `Secure`, а защищённые маршруты без сессии возвращают `404`.
- [ ] На чистой установке в `https` ссылка первичной настройки использует публичный домен. Если GitHub App использует возврат браузера, он проверен с HTTPS-адресом портала. Проверены чистая установка и переход с `local-http` с уже подключённым приватным проектом.
