# 15: Принять релиз на VM в локальном режиме

**What to build:** Владелец разворачивает полный релиз в `local-http`, подключается по SSH-туннелю и проходит рабочий сценарий платформы до появления домена.

**Blocked by:** 05 — Управлять браузерами и восстанавливать доступ, 11 — Подключить инструменты и индекс проекта, 13 — Публиковать записи в общую память, 14 — Управлять общими правилами.

- [ ] На чистой Ubuntu Server 26.04 LTS установка проверяет готовность критических служб, выдаёт локальную ссылку настройки владельца и показывает пустой список проектов. Вход через SSH-туннель проходит при закрытых публичных веб-портах.
- [ ] Владелец один раз подключает GitHub и добавляет два разрешённых приватных репозитория из портала. Проекты достигают готовности с индексами, открываются в Canvas и доступны из терминала. Codex по подписке и Qwen выполняют задачи с вызовом инструментов в обоих интерфейсах.
- [ ] В двух проектах проверены ограничения Git, сетевые границы и остановка mihomo на тестовой VM, раздельная память проекта, публикация общей записи владельцем и получение общих правил обоими агентами.
- [ ] Проверены срок и одноразовость активации, лимит регистрации после перезапуска, параллельная подача одного TOTP, продление при посещении, истечение при бездействии и восстановление. Отзыв браузера с открытым Canvas закрывает соединение, запущенная задача агента продолжает выполняться.
- [ ] Повторная установка тем же релизом и повтор после исправленного сбоя сохраняют рабочие копии, пакеты в песочницах, историю, индексы, память, сессии и секреты. Изменённая управляемая конфигурация применяется после проверки. Зафиксированы шаги и результаты приёмки.
