# 08: Запустить Qwen Code через шлюз моделей

**What to build:** Владелец выполняет задачу через Qwen Code из терминала песочницы, используя выбранную модель через внутренний шлюз.

**Blocked by:** 06 — Запустить постоянную песочницу проекта.

- [ ] Qwen Code выполняет задачу с разрешённой моделью и вызовом инструмента внутри песочницы проекта.
- [x] Шлюз применяет список разрешённых моделей и лимиты проекта. Проверены отказ при запросе запрещённой модели и поведение при исчерпании лимита.
- [x] Из песочницы доступны разрешённые вызовы шлюза. Ключи провайдеров и настройки других проектов недоступны.

### 2026-11-11 — подготовка реализации

- Задача ведётся в `codex/qwen-model-gateway` от `main` (`b1095ba`). Зависимость № 06 выполнена; в `main` также есть постоянные проекты с GitHub из задачи № 07.
- Предложены две границы проверки: HTTP API шлюза (разрешённые модели, лимиты и изоляция проектов) и команда Qwen внутри постоянной песочницы (ответ модели и выполнение инструмента). Подтверждение владельца ожидается.
- Для сквозной приёмки необходимо выбрать провайдера и модель. Ключ провайдера должен храниться вне песочниц и Git.
- Обязательные проверки должны выполняться на целевой Linux-машине после восстановления доступа. На Windows и WSL проверки не запускались.
- Подключение шлюза должно сохранить существующие рабочие копии, установленные пакеты и настройки постоянных контейнеров. Критерии приёмки остаются открытыми.

### 2026-11-11 — начало реализации

- Владелец подтвердил проверки API шлюза и запуска Qwen в песочнице. Для реальной приёмки выбран Alibaba Cloud Model Studio через OpenAI-совместимый API.
- Доступ к целевой Ubuntu восстановлен. Первый тест выполнен до реализации и после неё: разрешённый запрос и описание инструмента доходят до тестового провайдера; ключ провайдера отсутствует в настройках клиента.
- Шлюз использует отдельные ключи проектов, чтобы подключение не требовало пересоздания существующих контейнеров. Model Studio CLI устанавливается вне песочниц.

### 2026-11-11 — уточнения владельца

- SSH должен принимать ключи с любого IPv4, без парольной аутентификации.
- Все песочницы делят общий предел 80% физической RAM и 80% суммарной мощности CPU VM. Индивидуальные квоты RAM/CPU отменены; ресурсы пересчитываются при загрузке и повторной установке. Диск пока ограничен прежними 4 ГиБ на проект.
- Подготовка Qwen не должна блокировать обычный вход в терминал. Для существующих проектов предусмотрена отдельная команда `ai-sandbox qwen-setup`.

Автоматические HTTP-тесты также проверили конкурентный учёт квот, сохранность счётчиков после перезапуска, потоковые ответы, замену ключа провайдера и отзыв ключа проекта.

Такая же ошибка наблюдалась для исходной и стандартной моделей. Требуется подтвердить доступ через API в Model Studio, после чего выполнить сквозную проверку инструмента Qwen.

### 2026-11-11 — замена ключа и региона провайдера

- По данным владельца заменены ключ и endpoint Model Studio на регион Франкфурт. Ключ извлечён из предоставленного CSV без публикации его содержимого, сохранён в закрытых файлах VM; ключи проектов не менялись. Установщик успешно применил новый endpoint и правило исходящего трафика.
- Новый ключ проходит проверку каталога: `/models` отвечает HTTP 200 и содержит `qwen3.8-flash`. Прямой вызов `/chat/completions` и сквозная приёмка Qwen всё ещё блокируются ответом `403 AccessDenied.Unpurchased`; проверки API шлюза, запрета модели и квоты проходят.
- У Model Studio CLI 2.8.5 обнаружена ошибка обработки успешного ответа при `auth login`: HTTP 200 с кодом SUCCESS трактуется как ошибка. Новый ключ и хост сохранены через штатные `config set`; закрытый файл настроек проверен без вывода значений.
- Безопасная диагностика последнего запроса (время, регион, модель, HTTP-код и Request ID) сохранена на VM. Требуется проверить активацию услуги Model Studio или обратиться в поддержку провайдера, если услуга уже активирована. Нового ключа для продолжения диагностики не требуется.
