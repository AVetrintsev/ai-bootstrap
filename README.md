# ai-bootstrap
Личная платформа для разработки с ИИ

## Подготовка VM и исходящего трафика

В примере `ssh.allow_from_any_ipv4: true` разрешает SSH с любого IPv4-адреса. Вход остаётся только по SSH-ключу: парольная аутентификация SSH отключена. Пароль `sudo` подтверждает административные действия уже после входа. Для ограничения источников вместо этого флага можно задать `ssh.admin_ipv4`; одновременно использовать оба параметра нельзя.

Нужна выделенная Ubuntu Server 26.04 LTS на `amd64` с SSH по ключу на TCP 22, стандартным DNS Ubuntu через `systemd-resolved` и доступом к консоли VM. Первый запуск требует доступа к репозиторию Ubuntu и GitHub. Установщик проверяет настройки SSH и останавливается, если находит блоки `Match`, которые могут переопределить политику аутентификации.

1. Возьмите `bootstrap.sh` из выбранного релиза и запишите полный SHA его коммита. Для приватного репозитория добавьте отдельный ключ развёртывания с правом чтения. На VM положите приватный ключ в `/root/.ssh/ai-bootstrap-deploy` с правами `0600`, а проверенные ключи SSH-хоста репозитория в `/root/.ssh/ai-bootstrap-known_hosts`.
2. Скопируйте `config.example.yaml` за пределы Git в `config.yaml` и выставьте права `0600`. Укажите фактические IPv4-адреса или CIDR администратора, видимые серверу SSH. В `mihomo.profile` задайте рабочие узлы и правила. Используйте IP узлов или настройте `dns.proxy-server-nameserver` для их разрешения без системного DNS.
3. Из каталога с рабочим YAML запустите установку. `--config` можно опустить, если файл называется `./config.yaml`.

   ```bash
   sudo ./bootstrap.sh git@github.com:OWNER/REPO.git COMMIT_SHA --config ./config.yaml
   ```

Bootstrap использует `git` и клиент `ssh`, загружает закреплённый коммит в закрытый каталог `/opt/ai-bootstrap/releases` и запускает его `install.sh`. Версия mihomo и SHA-256 архивов mihomo и Ubuntu Base находятся в `release.env`. Пакеты ОС берутся из репозиториев Ubuntu.

Профиль применяется целиком. Сохраните параметры TUN и DNS из примера и завершите список правил `MATCH,REJECT` либо явно разрешите прямой выход для остального трафика через `MATCH,DIRECT`. Это исключает неявный прямой выход, когда выбранный узел не поддерживает протокол запроса. VM управляет маршрутами через интерфейс `ai-mihomo`, таблицу `41110` и правило с приоритетом `100`. Исходящий IPv4 идёт через TUN, включая трафик по правилам `DIRECT`. Соединения самого mihomo, ответы разрешённым клиентам SSH и DHCP обслуживаются отдельными правилами. Внешний IPv6 блокируется. Используйте VM без другого firewall или сетевой политики, которые управляют теми же маршрутами либо очищают таблицы nftables.

## Локальный HTTP через SSH

Выберите `portal.transport: local-http` в YAML. Домен и ожидаемый публичный IPv4 в этом режиме не нужны. После проверки DNS и исходящего HTTPS через mihomo установщик запускает Nginx с единственным веб-входом на `127.0.0.1:8080` и проверяет его ответ. Шаги публичного DNS, ACME и Globalping получают статус `SKIP`.

С компьютера, чей адрес указан в `ssh.admin_ipv4`, откройте туннель. Подставьте имя пользователя SSH и адрес VM вместо `USER@AI_HOST`. Ключ SSH должен разрешать локальное перенаправление на `127.0.0.1:8080`.

```bash
ssh -4 -NT -o ExitOnForwardFailure=yes -L 127.0.0.1:8080:127.0.0.1:8080 USER@AI_HOST
```

Откройте ссылку активации из вывода установщика в браузере с работающим туннелем. При запуске без интерактивного терминала получите ссылку следующей командой на VM. Установщик выводит ссылку только в терминал, чтобы она не попала в журнал.

```bash
sudo runuser -u ai-portal -- /usr/bin/python3 -I /usr/local/libexec/ai-bootstrap/portal.py activation http://localhost:8080
```

Отсканируйте QR-код в Google Authenticator и подтвердите первый шестизначный код. Ссылка действует 24 часа и закрывается после активации. Команда повторно показывает действующую ссылку или выдаёт новую, если срок старой истёк до активации. После активации команда ничего не выводит.

Сохраните ссылку «Зарегистрировать браузер» из портала. Откройте её в новом браузере и введите текущий шестизначный код. Для каждого браузера дождитесь нового кода. После трёх ошибок за скользящий час регистрация временно блокируется для всех адресов. Действующие сессии продолжают работать. Через SSH-туннель Nginx видит подключения как loopback.

Без сессии `/`, `/api/status` и `/api/test-stream` отвечают `404`. После регистрации открывается портал, а тестовый поток отправляет событие `ready` и сигналы поддержания соединения. После отзыва или истечения сессии поток закрывается. Повторный запуск установщика сохраняет состояние. С компьютера с туннелем проверьте прямой доступ к VM командой `nmap -sT -Pn -p 80,443,8080 AI_HOST`. Ни один из трёх портов не должен иметь статус `open`.

Для режима `https` установщик проверяет формат `portal.domain` и `portal.expected_ipv4`. Публичный HTTPS будет настраиваться в отдельной задаче.

## Управление браузерами

На главной странице видны имя каждого действующего браузера, даты регистрации и последней активности, а также срок действия сессии. Там же можно переименовать браузер или отозвать его сессию. Все даты указаны в UTC.

Открытие главной страницы в браузере и успешные действия управления продлевают текущую сессию на 30 дней. Фоновые запросы и открытые потоки сохраняют прежний срок действия. Для продления при открытии страницы браузер должен передавать заголовки Fetch Metadata. Управление браузерами продлевает сессию и без этих заголовков.

## Восстановление доступа к порталу

При утрате доступа выполните команду в приватном сеансе SSH или в консоли VM.

```bash
sudo runuser -u ai-portal -- /usr/bin/python3 -I /usr/local/libexec/ai-bootstrap/portal.py recover http://localhost:8080
```

Команда сразу отзывает все сессии, закрывает прежние ссылки и выдаёт одноразовую ссылку на 24 часа. Откройте её через туннель, добавьте новый TOTP в приложение-аутентификатор и подтвердите код. Новая ссылка регистрации появится в портале. Повторный вызов `recover` заменяет ожидающую ссылку восстановления.

Если раскрылась только ссылка регистрации, замените её отдельной командой. Действующие сессии и TOTP сохранятся.

```bash
sudo runuser -u ai-portal -- /usr/bin/python3 -I /usr/local/libexec/ai-bootstrap/portal.py rotate-registration http://localhost:8080
```

## Проверка и повторный запуск

Установщик проверяет DNS и HTTPS до `example.com`. Рабочий профиль должен разрешать этот запрос. При сбое исправьте причину из строки `ERROR` и повторите ту же команду. Скачанный и проверенный архив сохраняется в `/var/lib/ai-bootstrap`. Если для нового релиза нужно подготовить архив без работающего интернета на VM, положите файл с именем из релиза в этот каталог через SSH. Установщик сверит контрольную сумму.

На тестовой VM откройте второе SSH-подключение из разрешённой сети. Проверьте запрос через прокси, запрос по явному правилу `DIRECT`, системный DNS и прямой DNS-запрос на внешний IPv4. Затем остановите `ai-bootstrap-mihomo.service` и проверьте, что новое IPv4-подключение по IP и DNS-запрос завершаются ошибкой, а новое SSH-подключение по ключу проходит. Запустите службу снова и повторите установку. Проверьте также, что после перезагрузки сохраняются доступ по SSH, DNS и фильтрация.

Запускайте тесты на целевой VM с пакетами `python3-yaml`, `python3-cryptography` и `python3-qrcode`.

```bash
python3 -m unittest discover -s tests
```

## Постоянные песочницы проектов

Добавьте в рабочий YAML раздел `sandbox` (для начала достаточно `sandbox: {internal_tcp: []}`) и повторите установку. После этого на VM владелец создаёт песочницу и открывает её терминал:

```bash
sudo ai-sandbox create demo
sudo ai-sandbox shell demo
```

Имя проекта начинается со строчной латинской буквы и содержит до 24 букв, цифр или дефисов. Повторный `create` запускает прежний контейнер. Для разовой команды передайте её после имени проекта, например `sudo ai-sandbox shell demo id`.

У каждого проекта свой пользователь VM из зарезервированного диапазона UID 60001–60999, собственное хранилище Podman и отдельный диск 4 ГиБ. На проект выделяется до одного ядра CPU, 384 МиБ оперативной памяти и 256 задач. В терминале доступен `root` контейнера. Файлы и установленные пакеты сохраняются на диске проекта, а контейнер запускается при загрузке VM.

При полном заполнении диска Podman может получить ошибку записи служебного состояния. Доступ восстанавливается после освобождения места на диске проекта.

Первый `create` загружает закреплённый архив Ubuntu Base с `cdimage.ubuntu.com`. Если профиль ограничивает загрузку, администратор может положить архив из `release.env` в `/var/lib/ai-bootstrap/`. Команда проверит SHA-256 перед импортом. Для установки пакетов в терминале профиль mihomo должен разрешать выбранные зеркала Ubuntu.

Внешние подключения и DNS идут через mihomo. При включённых песочницах узлам mihomo и его резолверам нужны публичные адреса. Firewall проверяет адреса соединений, которые mihomo открывает на VM, в том числе после DNS. Используйте доверенные узлы выхода без маршрута к защищённым внутренним службам. Локальный DNS на порту 1053 доступен службам VM. Поле `sandbox.internal_tcp` открывает прямой доступ к указанным частным IPv4 и TCP-портам других машин. Список по умолчанию пуст. TCP/53, адреса самой VM и адреса метаданных облака закрыты.

Для проверки на целевой VM запустите `sudo bash tests/accept_sandbox.sh before`. Проверка создаёт проекты `accept-a` и `accept-b`, устанавливает пакет и ненадолго останавливает mihomo. При необходимости передайте разрешённое зеркало Ubuntu вторым аргументом, например `http://ru.archive.ubuntu.com/ubuntu`. После повторного запуска установщика и перезагрузки VM выполните `sudo bash tests/accept_sandbox.sh after`.

## Приватные проекты GitHub

На VM включите `sandbox` и установите релиз. В GitHub создайте [выделенное приватное GitHub App](https://github.com/settings/apps/new) для этой платформы. Отключите вебхуки и оставьте поля возврата пустыми. Дайте приложению разрешение **Repository permissions → Contents → Read-only** для клонирования или **Read and write** для отправки изменений. Правила веток GitHub применяются к операциям приложения.

Запишите числовой **App ID**, сгенерируйте приватный ключ и передайте файл по SSH в закрытый каталог на VM. Создайте его командой `mkdir -m 0700 ~/github-app-key`. Установите ключ с доступом для службы проектов и уберите временную копию после проверки установки.

```bash
printf '%s\n' 'APP_ID' | sudo tee /etc/ai-bootstrap/github-app-id >/dev/null
sudo install -o root -g ai-github -m 0640 ~/github-app-key/github-app.private-key.pem /etc/ai-bootstrap/github-app.pem
```

Через SSH-туннель откройте портал и выберите **Проекты → Подключить GitHub**. Откройте ссылку установки и выберите **All repositories** для доступа ко всем репозиториям аккаунта или **Only select repositories** для доступа к указанным репозиториям. Вернитесь во вкладку портала и подтвердите подключение. В форме **Добавить проект** появятся доступные приложению приватные репозитории.

Выберите репозиторий и обновите страницу проектов, чтобы увидеть статус подготовки. У каждого проекта своё имя песочницы `gh-<ID>`. После статуса **Готов** откройте терминал на VM и проверьте рабочую копию.

```bash
sudo ai-sandbox shell gh-123
cd /workspace/repo
git remote -v
git ls-remote origin
```

Git запрашивает у службы новый короткоживущий токен для репозитория этой песочницы. Удалённый адрес Git хранится без учётных данных. Для проверки изоляции добавьте два проекта и передайте их имена из портала и полные имена репозиториев. Команда проверит обе рабочие копии, доступ Git и отказ GitHub API при обращении с токеном каждого проекта к соседнему репозиторию.

```bash
sudo bash tests/accept_github_projects.sh gh-123 OWNER/FIRST gh-456 OWNER/SECOND
```

При сбое выберите **Повторить добавление**. Портал использует прежнюю песочницу и проверяет, завершилось ли клонирование. **Удалить проект** требует отдельного подтверждения и удаляет диск песочницы вместе с рабочей копией и пакетами. Репозиторий остаётся доступен в GitHub.

Если подготовка завершается ошибкой, на VM проверьте `sudo journalctl -u 'ai-bootstrap-projects@*.service'`. Профиль mihomo должен разрешать `api.github.com`, `github.com` и используемые зеркала пакетов Ubuntu.
