# Трекер задач: локальный Markdown

Задачи и спецификации проекта хранятся в `.scratch/`.

## Соглашения

- Одна функциональность — один каталог `.scratch/<feature-slug>/`.
- Спецификация: `.scratch/<feature-slug>/spec.md`.
- Каждая задача — отдельный файл `.scratch/<feature-slug>/issues/<NN>-<slug>.md`.
  Нумерация начинается с `01` внутри каталога функциональности.
- Состояние triage записывай строкой `Status:` в начале файла.
  Значения определены в `triage-labels.md`.
- Комментарии и историю обсуждения добавляй в конец файла под `## Comments`.

## Публикация задачи

Когда навык просит опубликовать задачу в трекере, создай отдельный
Markdown-файл по указанной структуре, при необходимости создав каталог.

## Чтение задачи

Когда навык просит получить задачу, прочитай файл по указанному пути.
Если указан только номер, ищи его в каталоге текущей функциональности.
Если контекст не определён и найдено несколько совпадений, уточни путь.

## Операции wayfinder

- Карта исследования: `.scratch/<effort>/map.md` с разделами
  `Notes`, `Decisions-so-far` и `Fog`.
- Дочерняя задача: `.scratch/<effort>/issues/<NN>-<slug>.md`,
  нумерация с `01`; исследуемый вопрос помещается в тело файла.
- Поле `Type:` содержит `research`, `prototype`, `grilling` или `task`.
- Для задач wayfinder поле `Status:` отражает ход исследования:
  `open`, `claimed` или `resolved`.
- Зависимости указываются строкой `Blocked by: NN, NN`.
  Задача разблокирована, когда все перечисленные задачи имеют `resolved`.
- Следующая задача — первая по номеру среди открытых,
  разблокированных и ещё не взятых в работу.
- Перед началом работы установи `Status: claimed` и сохрани файл.
- После завершения добавь ответ под `## Answer`, установи
  `Status: resolved` и добавь краткий вывод со ссылкой на задачу
  в раздел `Decisions-so-far` файла `map.md`.
