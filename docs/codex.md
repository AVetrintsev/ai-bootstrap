# Codex по подписке

В портале откройте **«Подключение Codex» → «Войти в ChatGPT»**, перейдите по ссылке и подтвердите одноразовый код. В настройках безопасности ChatGPT должен быть разрешён вход по коду устройства. После подтверждения обновите страницу портала. При первой настройке переход доступен с главной страницы сразу после регистрации браузера.

По умолчанию новые разговоры используют подписку ChatGPT. Портал отдельно показывает необходимость входа, исчерпание лимита и недоступность проверки. Ошибки не включают автоматическую оплату через API.

В портале нажмите **«Открыть»** и выберите проект в Canvas. В новом разговоре выберите профиль Codex. Для отдельной рабочей копии включите **Worktree** при создании разговора. Старые разговоры остаются в списке своего проекта. Для повторной подготовки сервера используйте **«Подключить Canvas»** или `sudo ai-sandbox canvas-setup gh-ID`.

В терминале проекта доступны:

```sh
codex                         # текстовый диалог, /exit для выхода
codex exec 'Выполни задание'   # одно задание
```

Это текстовый ACP-клиент; он не поддерживает произвольные флаги родного Codex TUI. `codex --acp` передаёт протокол Agent Server готовому `@agentclientprotocol/codex-acp` 2.6.0. Перевод ACP в app-server, события инструментов, планы, история и модели принадлежат upstream-адаптеру. Платформа проверяет доступ к проекту и параметрам доверенного процесса. История хранится на доверенной стороне; смена способа оплаты требует переподключения.

Для выбора reasoning используется собственный каталог адаптера с идентификаторами `model[effort]`. SDK 1.62 предпочитает отдельный config option модели, но не показывает отдельный effort. Совместимость ограничена исключением этих двух config options из ответа: каталог и `session/set_model` не преобразуются. При обновлении SDK эту совместимость нужно перепроверить и удалить, если появится штатный выбор effort.

## Граница доступа

- Закреплён полный официальный пакет Codex 0.166.0, включая code-mode-host и exec-server. SHA-256 записан в `release.env`.
- Учётные данные ChatGPT находятся в `/var/lib/ai-codex/auth` (`0700`, пользователь `ai-codex`). Каталог не монтируется в песочницы. Службы не записывают сообщения, коды входа или токены в журнал.
- Процессы проектов используют общий `auth.json` и общий `auth.lock`, чтобы вход и обновление токенов сохраняли штатную блокировку Codex при одновременной работе.
- Песочница видит только свой Unix-сокет `/run/ai-bootstrap-git/codex.sock`. API авторизации, hooks, произвольная конфигурация, клиентские MCP-команды и внешние image URL недоступны. Разрешены `/workspace/repo` и зарегистрированные Git worktree этого проекта; пути проверяются внутри контейнера, включая symlink. Сессии ограничены проектом и способом оплаты.
- Доверенный app-server получает `environments.toml` с единственной средой `project` и `include_local = false`. Через отдельный закрытый сокет служба проекта запускает `exec-server --listen stdio` в его rootless-контейнере. Сокет исполнителя доступен только службе Codex и не монтируется в контейнер.
- Доступность исполнителя проверяется перед открытием сессии и перед заданием. Ошибки выполнения обрабатывает upstream ACP. Новые сетевые порты не открываются. Модель и авторизация работают на доверенной стороне, shell и файловые операции — в контейнере.
- Отказ исполнителя и смена способа оплаты завершают запрос в Canvas. После восстановления службы такой запрос не должен выполняться повторно; для новой попытки отправьте новое сообщение. Терминальный клиент при отказе возвращает ненулевой код завершения.
- API-профиль хранится отдельно от подписки. Настройте его через `sudo ai-codex-api-key` (скрытый ввод), затем явно подтвердите **«Использовать платный API»** в портале. Адаптер читает ключ на хосте и использует временное хранилище авторизации Codex в памяти процесса.

Проверки выполняются только на целевой Linux VM. `tests/test_codex.py` проверяет публичный Unix-интерфейс с заменой внешнего процесса Codex; реальная подписка и исполнитель проверяются отдельно. Браузерный сценарий: `sudo PYTHON tests/accept_canvas.py gh-ID CHROMIUM codex` (для Qwen — `qwen`). Не запускайте несколько браузерных приёмок одновременно на небольшой VM.

`sudo python3 tests/accept_codex_isolation.py gh-ID` проверяет файловый протокол и MCP, недоступность контрольного файла хоста, а затем отказ открытой и новой сессии при остановке исполнителя. `sudo PYTHON tests/accept_codex_mcp.py gh-ID CHROMIUM PYTHON` временно подключает MCP-инструмент и проверяет его вызов самой моделью из терминала и Canvas; прежняя конфигурация восстанавливается в `finally`. Эти сценарии перезапускают службы выбранного тестового проекта: запускайте их, когда в нём нет пользовательских заданий.

Основание: [авторизация Codex](https://learn.chatgpt.com/docs/auth#login-on-headless-devices), [app-server](https://learn.chatgpt.com/docs/app-server), [протокол исполнителя 0.166.0](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/exec-server/README.md). Изменение версии требует повторения проверки изоляции, остановки исполнителя и обоих клиентских путей.
