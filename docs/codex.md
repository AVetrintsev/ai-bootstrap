# Codex по подписке

В портале откройте **«Подключение Codex» → «Войти в ChatGPT»**, перейдите по ссылке и подтвердите одноразовый код. В настройках безопасности ChatGPT должен быть разрешён вход по коду устройства. После подтверждения обновите страницу портала. При первой настройке переход доступен с главной страницы сразу после регистрации браузера.

По умолчанию новые разговоры используют подписку ChatGPT. Портал отдельно показывает необходимость входа, исчерпание лимита и недоступность проверки. Ошибки не включают автоматическую оплату через API.

Для существующего проекта выполните `sudo ai-sandbox canvas-setup gh-ID` либо повторите подключение Canvas из портала. Кнопка **«Открыть»** ведёт в разговор Codex; **«Qwen Code»** сохраняет доступ к прежнему разговору. В Canvas также доступны оба профиля. Их рабочая папка — `/workspace/repo`, контейнер и Git credential helper общие.

В терминале проекта доступны:

```sh
codex                         # текстовый диалог, /exit для выхода
codex exec 'Выполни задание'   # одно задание
```

Это ограниченный клиент платформы к настоящему Codex app-server; он не поддерживает произвольные флаги родного Codex TUI. `codex --acp` использует тот же интерфейс для Agent Server. История разговора хранится на доверенной стороне; Canvas может загрузить ранее созданный разговор своего проекта. Изменение способа оплаты требует нового разговора; существующий разговор сообщает об этом при следующем запросе.

## Граница доступа

- Закреплён полный официальный пакет Codex 0.166.0, включая code-mode-host и exec-server. SHA-256 записан в `release.env`.
- Учётные данные ChatGPT находятся в `/var/lib/ai-codex/auth` (`0700`, пользователь `ai-codex`). Каталог не монтируется в песочницы. Службы не записывают сообщения, коды входа или токены в журнал.
- Песочница видит только свой Unix-сокет `/run/ai-bootstrap-git/codex.sock`. Он принимает ограниченный набор ACP-запросов; API авторизации, произвольная конфигурация и регистрация сред недоступны. Дополнительные клиентские MCP-команды и рабочие каталоги за пределами `/workspace/repo` отклоняются.
- Доверенный app-server получает `environments.toml` с единственной средой `project` и `include_local = false`. Через отдельный закрытый сокет служба проекта запускает `exec-server --listen stdio` в его rootless-контейнере. Сокет исполнителя доступен только службе Codex и не монтируется в контейнер.
- Доступность исполнителя проверяется до и после задания; при отказе клиент получает явную ошибку. Новые сетевые порты не открываются. Модель и авторизация работают на доверенной стороне, shell и файловые операции — в контейнере.
- API-профиль хранится отдельно от подписки. Настройте его через `sudo ai-codex-api-key` (скрытый ввод), затем явно подтвердите **«Использовать платный API»** в портале. Сохранение ключа само по себе ничего не переключает.

Проверки выполняются только на целевой Linux VM. `tests/test_codex.py` проверяет публичный Unix-интерфейс с заменой внешнего процесса Codex; реальная подписка и исполнитель проверяются отдельно. Браузерный сценарий: `sudo PYTHON tests/accept_canvas.py gh-ID CHROMIUM codex` (для Qwen — `qwen`). Не запускайте несколько браузерных приёмок одновременно на небольшой VM.

Основание: [авторизация Codex](https://learn.chatgpt.com/docs/auth#login-on-headless-devices), [app-server](https://learn.chatgpt.com/docs/app-server), [протокол исполнителя 0.166.0](https://github.com/openai/codex/blob/rust-v0.166.0/codex-rs/exec-server/README.md). Изменение версии требует повторения проверки изоляции, остановки исполнителя и обоих клиентских путей.
